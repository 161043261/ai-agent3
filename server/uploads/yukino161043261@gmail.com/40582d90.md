# Brix 组件开发规范

将本 skill 作为指令集使用。按工作流顺序执行。Brix Comp 的**模板 / 样式 / 双向绑定 / 浮层 / 事件**等通用规则**整份继承自 magix-view**，本文件只列 Brix 专属差异（Handler、Comp 生命周期、数据回写、ADC）。

## 文件结构

Handler 与 Comp 同目录，统一放 `brix/`：

```
src/[项目名称]/views/pages/
└── brix/
    ├── {compName}.h.ts                 # Handler: 数据处理逻辑
    ├── {compName}.ts                   # Comp: 组件逻辑
    ├── {compName}.html                 # Template
    ├── {compName}.less                 # Style（可选）
    ├── {compName}-{handlerType}.h.ts   # 一个 Comp 对应多个 Handler 时的变体
    ├── {compName}-{compType}.ts        # 一个 Handler 对应多个 Comp 时的变体
    ├── {compName}-{compType}.html
    └── {compName}-{compType}.less
```

> **兼容旧结构**：存量项目可能仍是 `handlers/{name}.ts` + `comps/{name}.ts` 分离目录。阅读/修改存量按实际路径处理；**新建组件一律走 `brix/`**。

**compName 解析规则**（`adcConfig.properties.brix`）：

- 由 `properties.brix.compName` 决定；可为单层名，也可为 `/` 分隔多段路径（相对 `views/pages/brix/`），段内允许 `-`（如 `data-assets/metric-map`）。
- `adcConfig.code` 仅作提交数据 key，**不**决定文件路径；`adcConfig.name` 只用于展示。
- 有 `compType` → Comp 文件名 `{compName}-{compType}.ts/.html/.less`；有 `handlerType` → Handler 文件名 `{compName}-{handlerType}.h.ts`；有 `projectName` → 基准目录切到 `{projectName}/views/pages/brix/`。

## P0 红线（Brix 专属，必读）

### Comp 禁用清单（校验工具会自动拦截）

- **顶层 `init()` / `render()`：** 框架 `init` / `render` 已实现核心生命周期（见 `node_modules/@ali/common-code/src/magix-ports/brix/comps/compBaseOverloadMethod.ts`），重写会盖掉框架的初始化与 digest。
  - **替代**：默认走 Handler `process` 提供真实数据 + 模板守卫（`{{if list?.length}}` / `?.`）兜首屏；常量集中 / 稳定空态再用 `ctor` 叠加。详见 [comp.md §2.0](references/comp.md#20-需要默认状态怎么办)。
  - 误区：`process` 是 async 的，首渲必然先于其返回，**靠模板守卫**兜底，不是靠 process。
- **`mx_onTaskComplete` 体内调 `this.handleUpdate(...)`：** `status='finish'` 触发钩子；钩子里再 `handleUpdate` 让 `handler.update` 跑完后再次 finish → 钩子至少跑两轮，重复请求难幂等。
  - **替代**：自动副作用下沉 `handler.process`（async）一次性闭环。详见 [lifecycle.md](references/lifecycle.md)。
- **Comp 内 `await this.fetch(...)` / `Service.fetch(...)`：** 让链路从单向变双向，重复触发钩子的概率显著上升。
  - **替代**：Comp 事件只取参后 `this.handleUpdate({...})`；所有 `Service.fetch` 放 Handler 的 `process` / `update` / `afterSubComplete`。详见 [comp.md §2.2.1](references/comp.md#221-handleupdate-规则必读)。
- **新建 Handler 文件名 `*.handler.ts` / `*Handler.ts`：** 与 ADC 路径约定不符；仓库现存同类旧文件**不是**合法回退。
  - **替代**：`brix/{compName}.h.ts`（或 `{compName}-{handlerType}.h.ts`）。
- **Brix Comp 内 `this.createBrixIns(...)` / `this.initBrixNew(...)`：** Comp 的 `this` 是当前组件 view 实例，框架已通过 `_initForCommon` 把父 store 的 `brixSpaceName` 写入 `this.updater`；`createBrixIns(name)` 会把 `brixSpaceName` 直接覆盖成新 store，导致后续 `getBrixIns()` 与模板 `*brix-space-name="{{@brixSpaceName}}"` 都指向错误 store，父 store 数据被双向污染。
  - **替代**：Handler `process` 用 `useBrix(brixSpaceName)` 创建子 store、`init` 后返回 `{ data, brixIns }`；Comp 顶层声明 `isBrixSubPage: true`；模板绑 `*brix-space-name="{{@subBrixSpaceName}}"`。完整模式见 [nested-brix](references/nested-brix.md)。

### 其它 P0 硬约束

- **接口请求只用 `async/await + Service.fetch`：** 禁止 `requester`、`request['api_xxx'](...)`、`request.api_xxx(...)`、`xxx.req()`。详见 [service-fetch](references/service-fetch.md)。
- **非纯展示组件 `process` / `update` 必须返回 `data`：** 形如 `data: { [adcConfig.code]: value }`；纯展示组件才可省 `data`。
- **`this.handleUpdate()` 不能空参：** 至少传 `this.handleUpdate({})`，否则不会触发 handler `update`。
- **双向绑定值不会自动进 handler `params`：** `{{:variable}}` 只更新 Comp `updater`；要传给 handler 必须先 `const { variable } = this.updater.get()` 再显式 `this.handleUpdate({ variable })`。
- **Comp 只传业务值，Handler 负责 store 映射：** 不要在 Comp 中组装 `data: { [adcConfig.code]: ... }`。
- **若用 `mx_onTaskComplete`，本轮新返回字段不从 `this.updater.get()` 读：** 改用 `this.getBrixIns().getValue('xxx')`；`updater` 只用于本地幂等态。
- **格式化用 `FormatFn`：** Comp（`.ts`）从 `this.updater.get()` 解构（基类已注入，**不要 import**）；Handler（`.h.ts`）显式 `import FormatFn from 'magix-ports/public/format'`。**禁止**手搓 `toFixed` / `Math.round(x*100)+'%'` / 字符串千分位拼接 / 自写日期格式化，也禁止直接调 `formatFloat` / `formatInt` / `formatPer` / `formatCash` / `formatMoney`。详见 [magix-view 的 format-utils](../magix-view/references/format-utils.md)。
- **Handler 异常提示只用 `mx_brix_exception`：** 禁止在 Handler 中尝试调用视图方法（`alert`、`gmessage`、`this.gmessage()` 等）；接口失败等需要提示用户的场景，在 `process` / `update` 返回值中设置 `mx_brix_exception` 字段。详见 [handler-exception](references/handler-exception.md)。

### mxc-check 构建期 P0 提示

Brix Comp（`.ts` / `.html` / `.less`）继承 **magix-view 的 mxc-check P0 总表**，整份按 [magix-view 的 mxc-check 拦截清单](../magix-view/SKILL.md#mxc-check-构建期-p0-拦截清单) 落实。Brix 高频踩坑点：

- 缺括号事件：`mx-click="addRow()"`，不要 `mx-click="addRow"`（`mxc.tmpl-attr-mxevent.missing-paren`）
- 循环索引参数：删除 / 移动当前行时先写 `{{each rows as row index}}` / `{{each rows as row idx}}`，再写 `mx-click="del({index: {{@index}}})"` / `mx-click="del({idx: {{@idx}}})"`；`{{=@index}}` 是 P0，未声明索引却用 `{{@index}}` / `{{@idx}}` 是 P1 预警；详见 magix-view 的 [event-handling](../magix-view/references/event-handling.md)
- 双向绑定字段必须先在 updater 声明：Handler `process` 返回的 `rows` 数组里每行须有 `key`，模板才能写 `{{:row.key}}`（`mxc.tmpl-vars.unresolved-expr`）
- 自定义 class 必须在 less 中声明并 `Magix.applyStyle('@./{compName}.less')`（`mxc.tmpl-attr-class.unknown-class`）
- HTML 与 art 控制流闭合 + 不跨界（`mxc.checker-tmpl-unmatch.*` / `mxc.tmpl-art.*`）
- `mx-vframe src` 路径必须真实存在（`mxc.tmpl-customtag.file-not-found`）

Handler（`.h.ts`）只走 JS 校验链：

- `mxc.js-content.parse` / `mxc.js-module-parser.parse`：Handler `.ts` / 模块片段必须能被 acorn 解析；TS 语法错误、`import = require(...)` 等会直接 P0。

## P1 重要约定（Brix 专属）

- **新建 / 编辑 / 复制模式区分：** 复杂数据初始化抽成独立方法，不要把多种模式硬塞进一段分支。
- **表单字段优先 `{{:value&rules}}`：** 校验跟字段绑定在一起，不要分散到事件函数里。
- **复杂对象用 `*prop="{{@object}}"` 传递：** 不要拆成零散字段再手工拼回去。
- **父子嵌套是显式能力，不要隐式猜：** `adcConfig.properties.brix.displayType` 存在时当前组件是父组件；嵌套模式只分 `"custom"` 与 `"slot"`；父组件 Handler 必须实现 `afterSubComplete`，在所有子组件 ready 后做二次计算。详见 [parent-child](references/parent-child.md)。
- **通用规范（模板 / 样式 / 浮层 / 双向绑定）：** **直接遵循 magix-view**，本文件不重复。

## P2 工作方式

- **禁止过度设计：** Handler / Comp 都按单一路径、最简实现；不要无明确要求就加 polyfill / 多套参数形态 / 旧版回退 / 猜测性兜底。
- **修改已有代码精准手术：** 只改请求直接相关部分；匹配现有代码风格；自己引入的无用 import / 变量 / 函数清理掉，已有的不要删。

## 常见易错点（Brix 专属）

- **`compName` 不是 `code` / `name`：** 来自 `adcConfig.properties.brix.compName`，可为多段路径（段内允许 `-`），如 `data-assets/metric-map`。
- **想给模板默认数据 ≠ 写 `init()`：** Brix Comp 不能重写 `init` / `render`；默认走 Handler `process` 真实数据 + 模板守卫，常量 / 稳定空态用 `ctor` 叠加。反例（`init` 中 `set` 默认值）会触发 `render view error: Cannot read properties of undefined (reading 'length')`。详见 [comp.md §2.0](references/comp.md#20-需要默认状态怎么办)。
- **`this.handleUpdate()` 空参无效：** 至少传 `{}`。
- **双向绑定值不会自动同步到 handler：** `{{:value}}` 更新的是 Comp `updater`，不是 handler `params`。
- **store 回写逻辑不要写在 Comp：** Comp 传业务值，Handler 返回 `data: { [adcConfig.code]: ... }`。
- **接口请求不要写在 Comp：** Service.fetch / this.fetch 集中在 Handler 的 `process` / `update` / `afterSubComplete`。
- **`mx_onTaskComplete` 本轮新值不要从 `updater.get()` 读：** 改用 `this.getBrixIns().getValue()`。
- **`mx_onTaskComplete` 内禁止再 `handleUpdate`：** 自动副作用直接放 `handler.process` 闭环。
- **父子嵌套：** `afterSubComplete` 是关键生命周期；不要只写模板插槽不补 Handler 聚合。

## 3) 接口类型与字段语义查询（强制）

凡 Handler 需要读 / 写后端接口（`Service.fetch` / `req` / `this.fetch`）：

- **事实源唯一**：接口入参 / 出参的类型与字段语义**只能**来自 **get-rap-api-definition** Skill 的产出（RAP 上的真实 schema）。下列来源**均不**可作类型事实源：
  - `src/**/services/models.js` —— 仅有 URL + method，没有字段定义；该文件**只许由 `mm models` 生成**。**禁止手改 `models.js` 补接口**（须在 RAP 配置后本机同步；见 **get-rap-api-definition**、**mm-cli**）。
  - `src/**/services/requester.ts` / `request['api_xxx'](...)` —— 只是包装层。
  - 仓库里其他 Brix Handler 对同接口的解析代码 —— 可能本身就错或过时。
  - 用户口头描述、需求文档中的字段假设 —— 在没 RAP 校验前都视为「待校验」。
- **触发条件**：用户的需求文档 / ADC 描述 / Handler 实现中提及任何接口名（`api_xxx`）、接口路径（`/api/...`、`/gw/...`、`mtop.xxx`），都必须在写代码前调用 get-rap-api-definition 至少一次拿到 Req/Res；本地 `models.js` 有同名条目**不是**跳过该 Skill 的理由。
- **失败兜底**：get-rap-api-definition 首次返回为空时按 Skill 自带逻辑跑一次 `mm models --yes` 再重查；仍取不到 → 在 Handler 里以「未知 schema」标记并显式询问用户，**禁止**凭对接口语义的猜测写解析代码。

## 4) 完成前自检（最小必扫）

- **文件命名**：`compName` 已从 `adcConfig.properties.brix.compName` 解析（非 `code` / `name`）；新建 / 改名 Handler 为 `brix/{compName}.h.ts`；`tmpl: '@xxx.html'` 与当前 `.ts` 同名（共用属合法例外）。
- **Comp 顶层方法**：扫一遍 `View.extend({...})` 字面量内所有 key，确认**不含** `init` / `render`，只剩 `ctor` / `check` / 事件方法 / `mx_onXxx` / `handleXxx` 等合法成员；Comp 内**没有** `Service.fetch` / `this.fetch` / `createBrixIns` / `initBrixNew`。
- **首屏 undefined 已守卫**：模板里所有 `{{each list as x}}` / `list.length` / `obj.field.foo` 都已配 `{{if list?.length}}` 或 `?.`；不假设字段在 Handler `process` 返回前已存在。
- **数据回写**：非纯展示组件的 `process` / `update` 都返回 `data: { [adcConfig.code]: value }`；Comp 没在内部组装 `data` 回写。
- **`handleUpdate`**：均传入对象参数，不存在空参；双向绑定字段已从 `this.updater.get()` 取出再显式传入。
- **接口**：所有 `Service.fetch` / `this.fetch` 都在 Handler 内；用 `async/await`，非 GET 加 `isJson: true`；类型查询走 get-rap-api-definition 而非 `models.js`。
- **格式化**：Comp 端从 `updater.get()` 取 `FormatFn`（**不要 import**），Handler 端 `import FormatFn from 'magix-ports/public/format'`；未直接调 `formatFloat` / `formatInt` 等底层方法。
- **异常处理**：Handler 接口请求失败需要提示用户时，通过返回 `mx_brix_exception` 处理；Handler 内未直接调用视图层 `alert` / `gmessage` 等方法。
- **生命周期钩子**：若出现 `mx_onTaskComplete`，已确认无法用 `process` / `afterSubComplete` / ADC `observeMap` 替代；钩子体内**未**再调 `handleUpdate`；本轮新值改用 `this.getBrixIns().getValue()`。
- **父子嵌套**：父组件 Handler 已实现 `afterSubComplete` 并根据 `lastRunMethod` 区分 `'process'` / `'update'` / `undefined`（子组件联动）；返回值含 `data` 回写 store。
- **通用规范**：模板 / 样式 / 浮层 / 事件 / 注释等已按 **magix-view 的「完成前自检」** 落实（见 [magix-view](../magix-view/SKILL.md#3-完成前自检最小必扫)），本文件不重复。
